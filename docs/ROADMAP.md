# Дорожная карта

Для каждого этапа есть **критерий выхода**: пока он не выполнен, дальше не идём.
Если на этапе 3 или 4 идея не выживает, это штатный исход: возвращаемся к этапу 2 с новой гипотезой.

## Этап 0. Инфраструктура записи (код готов)
- [x] Стакан OKX с проверкой seqId/prevSeqId, тесты на синтетике
- [x] Запись сырых сообщений по часам, чтение, отчёт
- [ ] Живой запуск 10–15 минут, разбор расхождений
- **Выход:** `check_recording` на реальной записи: gap_events == gaps_detected, crossed == 0, задержка адекватна.

## Этап 1. Сбор данных
- [ ] Рекордер крутится на VPS/ноутбуке: BTC-USDT-SWAP и ETH-USDT-SWAP
- [ ] Автозапуск и рестарт при падении (systemd или аналог), мониторинг "жив ли процесс, растёт ли файл"
- [ ] Пересоздание подписки раз в N часов (страховка вместо отключённого checksum)
- [ ] Сверка стакана с REST-снапшотом раз в сутки (ловит подмену содержимого, которую seqId не видит)
- **Выход:** 7 дней записи без дыр дольше нескольких секунд; цель 30 дней.
- Темы: Sequence Numbers, Gap Detection, Exchange Time vs Receive Time, расхождение часов, таймауты, retries/backoff.

## Этап 2. Исследование сигналов (ноутбуки, не код боевой)
- [ ] Загрузка записи в pandas/parquet, ресемплинг по событиям или по времени (100 мс, 1 с)
- [ ] Признаки: mid, microprice, order book imbalance (топ-1, топ-5), signed trade volume, спред
- [ ] Гипотеза mean reversion: отклонение mid/microprice от короткой скользящей средней и возврат
- [ ] **Markout:** средняя доходность через 100 мс, 1 с, 5 с, 30 с после сигнала, до и после комиссий
- [ ] Half-life сигнала: на каком горизонте он умирает
- [x] Журнал прогонов (`hftlab.runs`) и выгрузка в Obsidian (`hftlab.vault_export`)
- [ ] Walk-forward разбиение: обучаемся на прошлом, проверяем на будущем, никакого перемешивания
- **Выход:** есть сигнал, у которого expected markout после комиссий положителен на out-of-sample данных
  и не исчезает при небольших изменениях параметров.
- Темы: Microprice, OFI, Signal Decay, Expected Markout, Look-Ahead Bias, Multiple Testing, Overfitting.

## Этап 3. Симулятор исполнения (здесь умирает большинство идей)
- [ ] Модель пассивной заявки: где мы стоим в очереди, когда нас исполнят
- [ ] Задержки: наша реакция + сеть + подтверждение
- [ ] Adverse selection: исполняют чаще, когда цена идёт против нас. Считать markout только по исполненным заявкам.
- [ ] Комиссии maker/taker по реальному тарифу аккаунта
- **Выход:** стратегия остаётся прибыльной в симуляторе с консервативными допущениями (очередь в хвосте,
  пессимистичные задержки), на данных, которые не использовались при подборе параметров.
- Честное предупреждение: на публичных L2-данных очередь можно только оценивать, не знать. Это граница точности.
- Темы: Queue Position, Fill Probability, Adverse Selection, Maker/Taker, Slippage, Partial Fills.

## Этап 4. Исполнение и риск (всё ещё без реальных денег)
- [ ] Автомат состояний ордера: new → acked → partial → filled / canceled / rejected / unknown
- [ ] Race между fill и cancel, дубли и поздние fills, reconciliation позиции с биржей
- [ ] Лимиты: максимум позиции, максимум убытка в день, максимум заявок в секунду
- [ ] Kill switch: один вызов отменяет всё и закрывает позицию
- [ ] Идемпотентность: повторная отправка не создаёт второй ордер (clientOrderId)
- **Выход:** тесты на сбои (разрыв соединения, потерянный ack, дубль fill) проходят, позиция сходится с биржей.
- Темы: Pre-Trade Risk Checks, Cancel/Replace, Reject Codes, Drop Copy, Idempotency, Circuit Breakers.

## Этап 5. Paper trading
- [ ] Стратегия работает на живом потоке, ордера не отправляются, всё логируется
- [ ] Сравнение "что симулятор ожидал" и "что реально было бы"
- **Выход:** минимум 2 недели; расхождение с симулятором объяснено; нет необъяснимых убыточных режимов.

## Этап 6. Live на минимальном размере
- [ ] Сначала сумма, потерю которой вы спокойно переживёте
- [ ] Ежедневный разбор: PnL, markout, доля исполнений, adverse selection, отмены
- [ ] Стоп-критерий заранее: при просадке X или расхождении Y с симулятором стратегия выключается, без исключений
- Темы: Inventory Skew, Dynamic Widening, Regime Detection, Concept Drift.

## Этап 7. Скорость (только если есть что ускорять)
- Профилирование, потом оптимизация узкого места (Python → NumPy/Numba → Rust/C++ при необходимости).
- Ускорение не создаёт edge. Если на этапе 3 прибыли нет, этап 7 не нужен.

race conditions и thread safety, backpressure, расхождение часов, управление секретами,
failover/реконнект, feature flags и откаты, CI. Остальное (шлюзы, Saga, шардинг, k8s) для этого проекта не нужно.
